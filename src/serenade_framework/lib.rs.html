1//! # Serenade
2//!
3//! Serenade is a Symfony-oriented application framework for Rust: a kernel with
4//! bundles, a dependency-injection container, an event dispatcher, layered
5//! configuration, and optional components (HTTP, security, messaging, views,
6//! forms, ...) that applications compose.
7//!
8//! `serenade-framework` is the public entry point for normal Serenade consumers.
9//! It re-exports a curated, stable surface of the `serenade-*` implementation
10//! crates. Those crates stay independently published and usable; the facade
11//! never owns their implementation.
12//!
13//! Website: <https://serenade.rs>. Guides: <https://docs.serenade.rs>.
14//!
15//! ```toml
16//! [dependencies]
17//! serenade = { package = "serenade-framework", version = "1.0.0" }
18//! ```
19//!
20//! The `package` rename imports the crate as `serenade` instead of
21//! `serenade_framework` (`cargo add serenade-framework --rename serenade`).
22//!
23//! The executable named `serenade` is shipped by the separate `serenade-cli`
24//! package. The crates.io package `serenade` is unrelated to this project.
25//!
26//! ## Features
27//!
28//! The default build contains only the framework foundations ([`kernel`],
29//! [`config`], [`di`], [`event`]). It needs no web server, database, Leptos,
30//! or Rangular.
31//!
32//! | Feature | Module | Enables |
33//! | --- | --- | --- |
34//! | *(default)* | [`kernel`], [`config`], [`di`], [`event`] | Foundations |
35//! | `console` | `console` | `serenade-console` |
36//! | `bundle` | `bundle` | `serenade-bundle` |
37//! | `http` | `http`, `http::client` | `serenade-http`, `serenade-http-client` |
38//! | `http-actix` | `http::actix` | `http` + `serenade-http-actix` |
39//! | `http-axum` | `http::axum` | `http` + `serenade-http-axum` |
40//! | `http-client-reqwest` | `http::client::ReqwestHttpClient` | Reqwest outbound client |
41//! | `session` | `session` | `serenade-session` |
42//! | `security` | `security` | `serenade-security` |
43//! | `security-oauth` / `security-ldap` | `security` | OAuth / LDAP helpers |
44//! | `validation` | `validator` | `serenade-validator` |
45//! | `lock` | `lock` | `serenade-lock` |
46//! | `rate-limiter` | `rate_limiter` | `serenade-rate-limiter` |
47//! | `scheduler` | `scheduler` | `serenade-scheduler` |
48//! | `scheduler-messenger` | `scheduler` | Scheduler dispatch through the message bus |
49//! | `messenger` | `messenger` | `serenade-messenger` |
50//! | `mailer` | `mailer` | `serenade-mailer` (no transport backend) |
51//! | `mailer-smtp` / `mailer-esp` | `mailer` | SMTP / ESP transports |
52//! | `notifier` | `notifier` | `serenade-notifier` |
53//! | `view` | `view` | `serenade-view` (engine neutral) |
54//! | `view-leptos-ssr` / `view-leptos-client` | `view` | Leptos SSR / hydrate support |
55//! | `form` | `form` | `view` + `serenade-form` |
56//!
57//! Integration features (`*-reqwest`, `*-smtp`, `*-esp`, `*-oauth`, `*-ldap`,
58//! `view-leptos-*`, `scheduler-messenger`) are never implied by their base
59//! feature.
60//!
61//! Crates outside this surface (for example `serenade-cache`,
62//! `serenade-workflow`, `serenade-translation`, `serenade-testing`) are used
63//! directly by depending on them.
64//!
65//! ## Example
66//!
67//! ```
68//! # extern crate serenade_framework as serenade;
69//! use serenade::prelude::*;
70//!
71//! struct Shop;
72//!
73//! impl BundleInterface for Shop {
74//!     fn name(&self) -> &'static str {
75//!         "shop"
76//!     }
77//! }
78//!
79//! let mut app = App::new(Environment::Test);
80//! app.register_bundle(Shop).expect("register");
81//! app.boot().expect("boot");
82//! assert_eq!(app.kernel().bundle_names(), vec!["shop"]);
83//! app.shutdown().expect("shutdown");
84//! ```

86/// Facade crate version (matches every `serenade-*` crate in the same release).
